# EUROWATCH repository and data audit

Audit date: 5 November 2026. Checkout: `main`, commit `21e9664`.

## Scope and confidence

Reviewed the tracked application, ingestion and classification code, local database schemas and aggregate counts, browser behavior, deployment documentation, Git history, dependency audit, and the university thesis record. Read the research databases using SQLite read-only connections. Ran the application against a disposable, small database fixture with local mode and automatic ingestion disabled, without loading the project’s `.env` or calling OpenAI.

This is a local audit, not a test of a deployed website. Hosting configuration, remote branch protection, deployed secrets, and the state of any hosted database were not inspected. The thesis abstract and metadata were accessible; the full PDF was not retrieved. No claim below depends on reading the full thesis.

The product brief was clarified during review: prioritize the existing database and a stable, usable exploration experience. The thesis is background, not the organizing principle of the product. A larger redesign and additional analysis come later.

## What exists

```text
European Parliament API + sitting HTML
               |
       fetch -> parse agenda / speeches
               |
       AI agenda-topic classification
               |
         main SQLite database
          /              \
 offline analytics       Express API
          |                  |
 analytics SQLite ------ cache
                             |
                   HTML / CSS / JavaScript UI
```

- `server.js`: 2,251 lines of route handling, SQL, initialization and maintenance actions.
- `public/script.js`: 2,328 lines of browser state, charts, filtering, exports and maintenance UI. Separate sitting, speech and speaker pages also exist.
- `src/core/`: reusable parsing, fetching, language detection, classification, group normalization and analytics code.
- `src/pipeline/`: incremental and bulk ingestion. `src/scripts/`: individual pipeline stages and maintenance utilities.
- `data/ep_data.db`: approximately 4.3 GB; `data/analytics.db`: approximately 3.6 MB. The local demo directory adds approximately 1.9 GB.
- 88 tracked files. Local `analysis/`, database files and many generated artifacts are ignored. A fresh clone does not include the usable dataset.
- A committed lockfile exists. There is one GitHub Actions workflow: Jekyll/GitHub Pages deployment, not Node application CI.

The existing separation into core, server and pipeline code is useful. SQLite indexes, paginated sitting metadata, stored source HTML, precomputed analytics, streaming CSV export with backpressure, and a local-mode guard on several newer maintenance routes are foundations worth retaining.

## What the data actually contains

These are measurements of the local files, not promises of exhaustive European Parliament coverage.

| Measurement | Full database | Local demo database |
|---|---:|---:|
| Sitting records | 1,512 | 334 |
| Sitting date range | 1999-07-20–2026-02-12 | 2020-01-13–2026-02-12 |
| Individual speech records | 368,934 | 368,934 |
| Speeches with no matching sitting | 0 | 283,390 |
| Speaker/MEP table records | 6,172 | 5,870 |
| Speeches with a macro topic | 359,001 | 359,001 |

The full database has 1,509 sittings represented by individual speeches, 7,469 distinct raw speaker names, 12,649 distinct agenda-topic labels, and 221 distinct macro-topic labels. Topic labels are derived from agenda headings; this pipeline does not independently classify the substance of every speech.

Important quality findings in the full database:

- **29,399 speeches have a non-null `mep_id` that does not match a row in `meps`.** No speech has a null ID, but that is not equivalent to successful linkage.
- **143,278 speeches lack a standardized political group** (38.8%). Missingness varies by year, so comparing groups across time needs explicit denominators and coverage.
- **5,453 of 6,172 speaker records lack a usable country** (88.3%, counting null, blank and `Unknown`). This is a speaker-record measure, not the percentage of speeches missing country.
- The speaker table contains 3,286 API-sourced records and 2,886 inferred historic records. Browser inspection exposed inferred labels containing agenda text or procedural fragments. These cannot all be presented as verified MEP identities.
- **948 speaker IDs have speeches associated with multiple standardized groups.** One affiliation per speaker cannot represent the history of every contribution.
- **5,050 speeches have macro-topic confidence of 0.2 or 0.3.** The classifier uses these values for fallbacks, so they should not silently count as confidently classified material.
- None of the 359,001 topic-labeled speeches has `macro_classified_by` or `macro_classified_at` populated. Existing provenance columns do not currently establish which model or classification run produced those labels.
- 62 speeches lack a language label; the stored schema defaults language to `EN`. Low missingness alone does not establish language accuracy. Detection is derived metadata, not proof of the original spoken language or translation status.
- No repeated `(sitting_id, speech_order)` combinations were found. No sitting orphans were found in the full database. These are useful checks, not a complete content-duplicate or parsing-accuracy audit.

Both analytics databases report 368,934 total speeches. In the demo, only 85,544 speeches join to retained sittings. Overall counts and date-based charts can therefore describe different populations. The demo must not become the basis of a public release until corrected and revalidated.

The latest sitting is in February 2026. “Current MEP,” “latest,” and “real-time” must be understood relative to a dataset snapshot, not the date a visitor opens the page.

## Concrete bugs and launch blockers

| Priority | Finding and evidence | Practical consequence |
|---|---|---|
| P0 | Several legacy POST routes omit `requireLocalRun`: `/api/refresh-all`, `/api/refresh-speeches`, `/api/refresh-meps`, `/api/refresh-perfect`, `/api/refresh-speeches-full`, `/api/refresh-sittings`, `/api/link-historic-meps`. Some delete or rewrite data. See `server.js:1586` onward. | Hiding the Data button and disabling `LOCALRUN` do not make the service read-only. Remove these routes from public mode. |
| P0 | Demo has 283,390 sitting orphans, verified by an explicit left join. | Counts, exports, profiles and charts can disagree. Do not reuse it as a trusted snapshot. |
| P0 | Fresh-table initialization creates `individual_speeches` without required columns such as `mep_id`, topic fields and standardized groups. A disposable initialization reproduced `SQLITE_ERROR: no such column: mep_id`. Optimization also runs before table creation. | A clean setup cannot reliably serve the same API as an evolved local database. Initialization must become explicit and ordered. |
| P1 | Warm-cache time series ignores `topics`, `top` and `all`. On the fixture, both `top=1` and `topics=NO_SUCH_TOPIC` returned 221 datasets. See `server.js:687`. | A filter can appear to work while the server returns unrelated data. Cached and uncached paths need the same contract. |
| P1 | `/api/speeches?personId=275948` returned no results while `/api/meps/275948/speeches` returned contributions. The former filters the sitting’s `personId`; the latter filters individual speeches. | “Sitting,” “speech” and “speaker” are inconsistently represented by APIs. Choose one meaning for each route. |
| P1 | `/api/speeches?limit=-1` returned all fixture sittings. Several list routes have no upper bound on limits. | Ordinary requests can become expensive, with avoidable memory pressure. |
| P1 | Local mode disabled: `/api/rebuild-database` returned 403, but `/api/refresh-perfect` reached its handler and returned 500 on undefined `req.body`; `/api/refresh-sittings` returned 500 because `fetchAllSittingsFromRemote` is undefined. | Old paths are both broken and inconsistently guarded. Retire unsupported endpoints. |
| P1 | `/api/ai/chat` accepts public requests, client-selected models, client-provided system messages, and up to 50 MB of JSON, without application authentication or quota controls. | If configured with a key, it exposes paid compute through the public app. Keep it disabled for the stability milestone. No paid request was made during this audit. |
| P1 | External text and generated Markdown enter `innerHTML` without a consistent sanitization boundary, including speaker rendering, speech content and `marked.parse()` output. | Text containing HTML can become executable page markup. Use text rendering or an explicit sanitized-HTML path. This was identified by source review, not an exploit test. |
| P1 | `npm audit --omit=dev` reported 31 affected packages: 3 critical, 20 high, 5 moderate, 3 low. Direct dependencies include Axios, Express, sqlite3, cld3-asm and PM2. | Review actual exposure and update/remove affected dependencies. Advisory counts are not proof every finding is exploitable in this app. Do not apply forced major upgrades without validation. |
| P1 | Main DB, analytics DB and in-memory caches have no shared release identifier. Cache `lastUpdated` records load time rather than the source snapshot’s age. | Visitors can receive internally inconsistent or stale results without knowing. |
| P1 | Storage uses `INSERT OR REPLACE`, multiple writes, unawaited statement callbacks and no explicit sitting-level transaction. Schema changes are attempted as one multi-ALTER operation with errors ignored. | Partial or failed ingestion can be reported as successful. Do not ingest into the browsing database. |
| P2 | Speaker speech ordering uses `s.date`, while stored sitting dates are predominantly in `activity_date`. Count queries and result queries also use different joins. | Chronology and pagination totals need reconciliation, especially with subset data. |
| P2 | Affiliation synchronization overwrites `meps.politicalGroup` with a most-frequent speech-derived role/group, then writes small groups as `Other`. API listing may choose a different first encountered speech group. | Profile metadata, exports and group charts can disagree and lose historical distinctions. Preserve raw values and keep display grouping separate. |
| P2 | Refresh considers `processed >= 0` success; bulk CLI can exit successfully after a partially failed run. Fetch failures are broadly treated as skips. The failure-log path points under `src/data`, rather than root `data`, with write errors swallowed. | Jobs can appear healthy while missing work. Fix before resuming regular ingestion. |

P0 means protect the dataset and prevent unsafe or incoherent serving first. P1 means required for the proposed stable playground. P2 items must be fixed where they affect the retained flows; unrelated pipeline improvements can remain offline backlog work.

## Usability observations

The UI renders and the main tabs can be opened. The issue is a lack of a coherent browsing experience and trustworthy context, rather than a complete absence of frontend code.

- The homepage opens with a large all-time speaker inventory and demographic charts. It does not first explain the corpus, snapshot date, or how to find an interesting speech.
- Speaker identities, parliamentary roles and political groups are mixed into one affiliation filter. Public copy refers visitors to maintenance actions that are hidden in public mode.
- Analytics presents hundreds of topics and several charts before establishing a useful default selection. Chart canvases have no equivalent accessible data tables.
- Navigation mixes tab state with separate HTML pages; going back can lose the previous exploration context.
- The main scripts contain global functions, unrelated legacy rendering paths and inline HTML/CSS. This makes local fixes harder to isolate.
- Chart.js and Marked are loaded from unversioned CDN URLs. Browser behavior can change independently of a repository release.
- Missing data, failed requests and genuine empty selections need separate, readable states. Some frontend loaders parse non-OK responses as though they were empty results.
- The standalone newest-sittings table headings do not match the shared script’s rendered column order.
- Full database download is separately configured and was unavailable on the audit fixture. Availability on a real host was not checked.

## Engineering and reproducibility

- All 71 local JavaScript files found across active and archived directories passed `node --check`. This verifies syntax only.
- No `test`, `lint` or build-validation scripts are defined in `package.json`. Existing files named `test-*` are manual/API/LLM utilities rather than an automated regression suite.
- The Jekyll workflow does not install or test the Node service. It deploys on pushes to `main`; there is no suitable application release gate in the checked-in workflow.
- `.gitignore` broadly ignores JSON and `analysis/`, including local analysis material under nested paths. Small fixtures, metadata and reproducibility files need intentional tracking rules.
- README claims MIT licensing, but no tracked LICENSE file exists. README also advertises `/api/search`, which is not implemented in the current server.
- `.env` and local SSH key files are present and ignored. Their contents were not read or included in this report. No tracked history for the exact `.env` or `eurowatchtool` paths was found; that is not a full secret-history audit.
- `.git` is approximately 1.7 GB. Investigate historical large blobs separately; do not rewrite history as part of routine stabilization.

## Reproducing the most important data checks

Open SQLite in read-only mode. Run these separately against the full database and any candidate subset:

```sql
SELECT COUNT(*) FROM individual_speeches;

SELECT COUNT(*)
FROM individual_speeches i
LEFT JOIN sittings s ON s.id = i.sitting_id
WHERE s.id IS NULL;

SELECT COUNT(*)
FROM individual_speeches i
LEFT JOIN meps m ON m.id = i.mep_id
WHERE m.id IS NULL;

SELECT COUNT(*), MIN(activity_date), MAX(activity_date)
FROM sittings;

SELECT COUNT(*)
FROM individual_speeches
WHERE political_group_std IS NULL OR TRIM(political_group_std) = '';
```

`PRAGMA foreign_key_check` alone is insufficient: the full database’s declared speech foreign key targets legacy `speeches`, not `sittings`, and it does not declare the speaker relationship. The full database passed that pragma despite its dangling speaker IDs.
